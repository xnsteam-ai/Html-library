Found the issue. In middleware.ts, token validation runs before the refresh check. When a token expires, the middleware rejects the request immediately instead of attempting a refresh.

middleware.ts typescript 
async function authMiddleware(req: Request) {
  try {
    const decoded = validateToken(req.headers.authorization);
    req.user = decoded;
  } catch (err) {
    if (err instanceof TokenExpiredError) {
      const refreshed = await refreshToken(req.cookies.refreshToken);
      if (refreshed) {
        req.user = refreshed.user;
        return next(req);
      }
    }
    return new Response('Unauthorized', { status: 401 });
  }
  return next(req);
}

JWT Token Refresh: Design & Rollout

Overview

Our API gateway authenticates every request with a short-lived JWT access token. This document describes the silent-refresh flow we just shipped.

The Fix

  • Transparent — valid sessions never see an interruption
  • Safe — a missing or invalid refresh token still returns 401
  • Cheap — refresh only runs on the expiry path
